# Codespaces Demo Deployment

Run the QloApps farmstay demo in a GitHub Codespace using the project's own
Docker stack. No credit card or external hosting required.

## How it works

- A `.devcontainer` boots with Docker-in-Docker and automatically runs
  `scripts/deploy-codespaces.sh` (postCreateCommand).
- The script:
  1. Converts `db/init/01-init.sql` (a MariaDB 11.x dump using
     `utf8mb3_uca1400_ai_ci` collations) to `utf8mb3_general_ci` so the pinned
     `mariadb:10.11` image can import the seed on a fresh volume.
  2. Generates a fresh `.env` (random DB password + cookie keys) on first run.
  3. Builds and starts `docker-compose.yml` + `docker-compose.codespaces.yml`
     and waits for the health checks.
- `docker-compose.codespaces.yml` bind-mounts `themes/` and `controllers/` into
  the web container, so frontend changes pulled from git are live without a
  rebuild.

## One-time boot

1. Push `db/init/01-init.sql`, `img/`, `upload/`, `download/` to the repo
   (see "Demo media" below) - a fresh clone cannot seed the demo without them.
2. Open the repo on github.com -> **Code -> Codespaces -> create on the
   feature branch**.
3. The postCreateCommand deploys automatically (first build takes several
   minutes). When the terminal shows "Demo ready", open the **Ports** panel,
   hover port 8080 and set it to **Public** to generate a shareable URL.

URLs: `http://localhost:8080` (frontend), `/hotel-admin` (back office).

## Refresh loop after code changes

```
git pull
docker compose -f docker-compose.yml -f docker-compose.codespaces.yml up -d --build
# or simply: bash scripts/deploy-codespaces.sh
```

- Frontend-only edits (themes/, controllers/): `git pull` is enough, the bind
  mounts serve the new files (clear themes cache if a Smarty template seems
  stale).
- Anything else (css/, js/, modules/, img/, Dockerfile): rebuild is required.

Committing/pushing to GitHub alone does NOT update a running Codespace - it is
a snapshot created from the branch. Pull (or recreate the Codespace) to pick up
new commits.

## Free-tier limits (GitHub personal account)

- 120 core-hours/month compute; a 2-core Codespace is ~60 hours of active use.
- 15 GB-month storage (one codespace disk is ~8-16 GB).
- No payment method needed; usage is blocked, not billed, once the quota ends.
- The Codespace (and the demo URL) stops when it shuts down and suspends after
  ~30 min idle. Fine for verification and short demos, not for 24/7 hosting.

## Always-on fallbacks (cardless)

- **Azure for Students**: with a university email, $100 credit / 12 months on
  a real VM - deploy the same compose stack there for a persistent demo.
- **InfinityFree**: shared PHP+MySQL hosting, no account gating; see the
  InfinityFree-Demo-Deploy plan (requires DB collation conversion, which
  scripts/deploy-codespaces.sh already automates for the dump, plus
  settings.inc.php and .htaccess regeneration).

## Troubleshooting

- **Empty DB or broken images on first boot**: the seed dump and/or `img/`
  were not in the repo when the Codespace was created. Push them, then
  `bash scripts/deploy-codespaces.sh` and recreate the db volume
  (`docker compose down -v`) to re-seed.
- **Build fails at the media `cp` step**: `img/`, `upload/` or `download/`
  missing from the build context - commit them.
- **Page renders but login cookies fail**: cookie keys were regenerated by a
  new `.env`; clear cookies and reload - expected on a fresh deploy.
- **Recovery mode during container creation**: `devcontainers/universal:2`
  carries a Yarn apt repo whose GPG key rotated, breaking the docker-in-docker
  feature install (`NO_PUBKEY 62D54FD4003F6525`). The devcontainer now uses
  `mcr.microsoft.com/devcontainers/base:ubuntu-24.04`; if the error returns,
  delete the Codespace and prebuild, then recreate.
