## Idea
Complete the farmhouse design-system transformation across the remaining stock surfaces of the QloApps child theme. Audit (done) shows redesigned = home, product page, room listings/category, header, hero search panel, discovery modules. STILL STOCK = footer content columns (blocksocial 'Follow us on', wkfooterpaymentblock, wkfooternotificationblock 'Subscribe', footer links column), breadcrumb, pagination, authentication/login, my-account, identity, addresses, order history/detail, cart (shopping-cart), one-page checkout (order-opc.tpl flow incl. new-account/edit-guest-info/carrier/payment steps and cart-total-block), order confirmation, CMS/contact/sitemap/stores/404/errors/maintenance. Approach per client decisions: branded footer replacement (drop empty/unconfigured blocks), restyle every remaining surface with the existing design-system.css/components.css tokens (cream #F7F4EF, forest #2F4A3C, terracotta #C46A3B, Fraunces/Manrope self-hosted fonts, fh- class naming, 44px targets, mobile-first, no horizontal overflow). CRITICAL INVARIANTS: preserve every QloApps/module hook, Smarty variable, form field name and JS contract in the booking flow (search_hotel_block_form fields, booking-form hidden inputs, HOOK_PAYMENT/wkcheckoutpaymentblock/emqCheckoutBlock output, order-opc step includes, displayCart*/displayBookingAction hooks). order-opc.css (1009 lines) and account.css/authentication.css exist but mostly target stock classes — rewrite templates with fh- markup then extend/align the CSS layer. Workflow: theme templates are live via the dev bind mount (clear smarty compile after tpl changes); module template overrides must be podman cp'd into the running container and baked via image rebuild at the end. Verify: full guest journey regression (search -> availability -> room -> occupancy -> cart -> checkout -> confirmation) at 375/768/1440, hook inventory renders, zero console/PHP errors, zero horizontal overflow; commit atomically per surface.
