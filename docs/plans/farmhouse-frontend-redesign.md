## Idea
Full visual redesign of the active QloApps child theme themes/my-farmhouse-child-theme into a modern, mobile-first, Booking.com-grade stay-discovery experience for the rural Uttar Pradesh farmhouse marketplace. Brand: revived farmhouse identity (recover palette/fonts from git history: Fraunces display font self-hosted with system-font body stack, warm earth tones). CRITICAL INVARIANT: every QloApps hotel hook, Smarty variable, form field name, selector, and JS contract must be preserved so search -> availability -> room -> occupancy -> cart -> checkout -> confirmation works unchanged (wkroomsearchblock form, hotel cart/checkout templates, occupancy.js/product.js/order-opc.js Bootstrap-class dependencies). Runtime must be restored first (user removed podman/DBs; podman 5.8.4 + podman-compose remain; rebuild stack from docker-compose.yml + dev override, verify :8080). CSS strategy: keep stock global.css + page css as functional base (Bootstrap 3 grid/JS compat), add a modern override layer (design-system.css + components.css + per-page css) loaded after stock in header.tpl. Performance: system font stack for body, one self-hosted display font (limited weights), lightweight vanilla JS for new interactions (no new jQuery), CSS-only interactions where possible, no carousels, small total load for slow guesthouse connections. Deliverables include: theme architecture summary, exact file paths with add/modify/delete modes, full hook inventory table (hook -> provider module -> template), per-page breakdown of template/partial/css/js transformation, Booking.com-style search bar spec (colors, elevation, date field handling, check-in/check-out quick links, guest/room selection, mobile/desktop/tablet wireframes + states), room-page booking widget spec (available dates, quantity, per-day price summary, policy, steppers, CTA), checkout flow + payment steps, mobile responsive behavior rules, and performance rules. All design decisions are recorded in a decision record section (brand, fonts, CSS strategy, runtime fix, imagery). Verification: restore runtime, clear smarty cache, visual QA each surface at phone/tablet/desktop with no horizontal overflow, confirm hooks/selectors preserved, update docs/CLIENT-REQUIREMENTS.md and commit atomically per surface.
