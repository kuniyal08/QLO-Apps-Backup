| # | Decision | Choice |

## 3. Booking.com-style Search Bar Spec

Surface: white elevated panel (radius lg, shadow raised), placed in-hero on homepage and sticky under header on category/room pages. Preserve EXACT field names and hooks of wkroomsearchblock:
- Form id `search_hotel_block_form`, POST; fields: hotel_location (text w/ autocomplete + dropdown from location-options.tpl), location_category_id (hidden), check_in_date (readonly), check_out_date (readonly), adult_count (select), child_count (select), number_of_rooms (select), submit `search_hotel_btn`. Hooks: displaySearchFormFieldsBefore, displaySearchFormFieldsAfter.
- Date fields: two text inputs styled as "Check-in date" / "Check-out date" with calendar icon; show quick-links (Today / Tomorrow / +2d / Next weekend) that fill both fields; retain readonly + JS datepicker contract used by occupancy.js/product.js.
- Occupancy: dropdown trigger showing "2 adults · 1 room" summary; panel has steppers (- / +) for adults, children, rooms, mirroring the existing occupancy dropdown pattern (occupancy_field.tpl) and writing the three select values.
- Desktop: single-row 4-5 column grid (location | check-in | check-out | guests | button), auto-submit on change via existing search JS contract (do not break request_uri/GET flow of categoryPageSearch).
- Tablet: 2-row grid (location full, dates row, guests + button row).
- Mobile (<768): stacked full-width fields with big touch targets; guests control opens bottom-sheet style panel; search button full-width primary.
- States: default, focus ring (forest green 2px), error border (red), disabled, loading (button spinner), results scroll.
- Wireframe (desktop):
  [Location ▾│ Check-in date ▾│ Check-out date ▾│ 2 adults · 1 room ▾][Search]
- Wireframe (mobile): stacked rows, full-width.

## 4. Room Page Booking Widget Spec

Right column (desktop, sticky under header, width ~360-400px); bottom sticky bar on mobile (<768) with total + "Book now" that expands to the full widget sheet.
- Widget card: white, radius lg, shadow raised. Contents:
  1. Dates: check-in / check-out date fields (readonly, same datepicker contract), quick-link chips.
  2. Guests/rooms: occupancy steppers (adults, children, rooms) writing occupancy[] inputs via occupancy_field.tpl contract (num_adults/num_children/room_occupancies hidden inputs, max_adults/max_children/max_guests/max_avail_type_qty caps, remove-room-link).
  3. Available dates hint: text of min/max stay or availability note from $room_type_info / $total_available_rooms (existing variables; no backend change).
  4. Price details: per-day price breakdown list (from cart/booking data: total_rooms_cost, total_extra_demands, total_additional_services, per-night rows where available in template vars), tax label (tax incl/excl) as existing.
  5. Policy text block (existing policy vars / modules).
  6. Quantity stepper (qty, quantity_wanted hidden, max_avail_type_qty cap) via quantity_field.tpl contract.
  7. CTA button "Book now" (primary, pill) submitting form id `booking-form`; preserve hidden inputs (token, id_product, add, dates, occupancy) and displayBookingAction hook output.
- Mobile bottom bar: sticky bottom, safe-area padding, shows price + dates + "Book now"; expands full widget sheet; close on backdrop tap.
- Accessibility: all steppers keyboard-operable; aria-live on price updates; contrast >= 4.5:1.

## 8. Mobile Responsive Rules

- Breakpoints: phone <768, tablet 768-1199, desktop >=1200; mobile-first authoring.
- No horizontal overflow at any width (acceptance criterion; test with QA captures).
- Header: drawer nav on phone (hamburger), horizontal compact bar on tablet, full bar desktop.
- Search bar: stacked on phone (bottom-sheet guests picker), 2-row tablet, 1-row desktop.
- Room page: sticky bottom booking bar on phone (expands to sheet), sidebar widget on desktop.
- Room cards: single-column stacked on phone (image top), 2-col tablet, 3-4 col desktop.
- Footer columns collapse to accordion on phone.
- Touch targets >=44px; keyboard focus states visible; reduced-motion respected.
- Hindi text wrapping: no fixed-width containers without overflow control.

## 9. Performance Rules

- Body copy: system font stack only. One self-hosted display font (Fraunces) with woff2 + font-display:swap, max 2-3 weights, latin subset (~<60KB total).
- New JS (theme.js): vanilla, defer, no jQuery import for new features; keep existing module JS untouched.
- No carousels anywhere (use CSS scroll-snap or static grids).
- CSS-only interactions preferred (hover/active/accordion via :target or checkbox where safe; drawer needs JS).
- Lazy-load below-fold images (native loading=lazy where template allows).
- Minimize reflows: contain animations to transform/opacity only.
- Target: total added JS < 25KB gz, added CSS < 30KB gz; no new external font/CDN dependencies (self-host everything).
- Clear cache/smarty/compile + cache/smarty/cache + cache/class_index.php after template/css changes; disable dev-mode cache for QA.

## 10. Non-Goals (this plan)

- No booking/pricing/availability backend changes; no new hooks (only restyle existing output).
- Razorpay/SMS/OTP/caretaker modules are separate workstreams (presentation placeholders only).
- Do not delete stock CSS files from disk (only stop loading where fully overridden).
