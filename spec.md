# QloApps Farmhouse Frontend Redesign — Master Spec

> **Audience:** any AI agent or developer working on this project. Read this before touching the theme.
> **Status:** Active — drives plan `farmhouse-frontend-redesign` (see `docs/plans/Rural-Marketplace.md`, `docs/specs/Rural-Frontend.md`).
> **Last verified:** runtime env + hook inventory (Aug 2026).

---

## 1. Project Context

- **Platform:** QloApps (PrestaShop 1.6.1.23 fork) — PHP 8.1–8.4, Smarty 3, MySQL/MariaDB. MVC + hook-based modules.
- **Product:** Rural Uttar Pradesh stay marketplace (~250 farmhouses / stay-in homes / cultural centers). Stays are the only bookable product; activities are informational only.
- **Active theme:** `themes/my-farmhouse-child-theme/` (full copy of `themes/hotel-reservation-theme/` parent, NOT a true inheriting child — it is the theme being actively developed).
- **Stack:** podman 5.8.4 + `podman-compose` (rootless), `docker-compose.yml` (db = `mariadb:10.11`, internal `db:3306`; web on host `:8080`). `docker-compose.dev.yml` bind-mounts `themes/`, `controllers/`, `cache/` for live editing.
- **`config/settings.inc.php` is regenerated by the container entrypoint from env each boot** (DB_HOST=`db`, DB_PORT=`3306`). Never edit it manually — it will be overwritten.

## 2. Mission

Redesign the active child theme into a modern, mobile-first, Booking.com-grade stay-discovery experience with a revived **farmhouse / rural UP** brand identity — **without changing any QloApps hotel, availability, cart, booking, payment, or admin contract.**

### Hard invariants (never break)

1. **Hooks:** every `{hook h='...'}` call in the theme templates keeps its name, position, and single render. Table in §6.
2. **Form contracts:** field names, form IDs, and selectors of `wkroomsearchblock` (`search_hotel_block_form`, `hotel_location`, `location_category_id`, `check_in_date`, `check_out_date`, `adult_count`, `child_count`, `number_of_rooms`, `search_hotel_btn`) and the booking form (`booking-form`, hidden token/id_product/add/dates/occupancy inputs) stay byte-identical.
3. **JS contracts:** `product.js`, `occupancy.js`, `order-opc.js`, `global.js`, `cart-summary.js` keep their element classes (`occupancy_count`, `qty_direction`, `room_occupancies`, `.dropdown-menu`, `.form-control`, Bootstrap grid) and behavior. New code must not break them.
4. **Bootstrap 3 classes:** QloApps JS depends on `.btn`, `.form-control`, `col-sm-*`, `.dropdown-menu`, `.modal`, etc. — keep them present; style via override CSS, never remove the classes.
5. **WhatsApp (emqmodules):** `emqPriceCheckBlock.tpl` (room page) + `emqCheckoutBlock.tpl` (checkout) are restyled only, logic untouched.

## 5. Architecture

```
themes/my-farmhouse-child-theme/
├── *.tpl                 # shell + page templates (modify)
├── _partials/            # booking-form, occupancy_field, quantity_field, room_type_list,
│                         # hotel_images, thumbnail, service-products*, order-* detail partials
├── css/
│   ├── global.css        # stock QloApps base — KEEP, loaded first
│   ├── *.css             # stock page css — KEEP as base
│   ├── design-system.css # NEW tokens/base override  (load AFTER stock)
│   ├── components.css    # NEW component override   (load AFTER design-system)
│   └── modules/          # stock module css
├── js/                   # stock QloApps JS — DO NOT modify contracts; theme.js is NEW
├── fonts/                # FontAwesome + NEW self-hosted Fraunces woff2
├── modules/              # theme-side template overrides (NEW dirs per module, files added)
└── mobile/               # legacy mobile theme — leave alone
```

**CSS load order (header.tpl):** stock global.css + page css → `design-system.css` → `components.css` → page-specific override (e.g. `home.css`). Specificity: override layer wins without `!important` where possible; use `!important` only for QloApps JS-toggled classes.

**JS strategy:** new interactions (nav drawer, sticky header, date quick-links, sticky booking bottom bar, mobile accordions) in NEW `js/theme.js` — vanilla, `defer`, no jQuery. Do not edit `product.js`/`occupancy.js`/`order-opc.js`/`global.js` except styling-neutral tweaks. No new jQuery plugins. No carousels — use CSS `scroll-snap` strips or static grids.

## 8. Booking.com-style Search Bar Spec

Surface: white elevated panel (`--fh-shadow-3`, radius `--fh-radius-lg`), floating over hero on homepage; sticky compact bar under header on category/room pages.

**Fields (byte-identical names):** `hotel_location` (text + autocomplete dropdown from `location-options.tpl`, hidden `location_category_id`), `check_in_date` (readonly), `check_out_date` (readonly), `adult_count`/`child_count`/`number_of_rooms` (selects). Submit `search_hotel_btn`. Keep `displaySearchFormFieldsBefore` / `displaySearchFormFieldsAfter` calls. Form: `search_hotel_block_form`, POST.

**Date fields:** two inputs styled as "Check-in date"/"Check-out date" with calendar icon; **quick-link chips** (Today / Tomorrow / +2 days / Next weekend) fill both fields — vanilla JS writes values then triggers the existing datepicker change contract used by `product.js`/`occupancy.js`. Keep readonly + existing datepicker widget behavior.

**Guests/Rooms:** dropdown trigger showing summary ("2 adults · 1 room"); panel with steppers for adults, children, rooms that write the three `<select>` values (mirror `occupancy_field.tpl` stepper pattern/classes).

**Responsive states:**
- Desktop (>=1200): single row — [Location][Check-in][Check-out][Guests ▾][Search button] (5-col grid).
- Tablet (768–1199): 2 rows — location full; dates row; guests + button.
- Phone (<768): stacked full-width fields; guests control as bottom-sheet style panel; search button full-width primary; hero search collapses to a single "Search stays" pill opening the form.

**States:** default / focus (2px `--fh-primary` ring) / error (`--fh-error` border) / disabled / submitting (button spinner, text "Searching…") / results returned (scroll to results). Wireframes in plan `farmhouse-frontend-redesign`.

## 9. Room Page Booking Widget Spec

Desktop: right column, sticky (top offset = header height), width ~360–400px. Phone: **sticky bottom bar** (safe-area padding) showing price + dates + "Book now"; tapping expands the full widget as a sheet with backdrop close.

Widget card contents (in order):
1. **Dates** — check-in/check-out readonly fields + quick-link chips (same contract as §8).
2. **Guests/rooms** — occupancy steppers per `occupancy_field.tpl` (adults, children, rooms; caps from `max_adults`/`max_children`/`max_guests`/`max_avail_type_qty`; hidden `occupancy[]` inputs; `remove-room-link` for extra rooms).
3. **Availability hint** — text from existing vars (`$room_type_info`, `$total_available_rooms`): "N rooms available" / min-stay note. No backend change.
4. **Price details** — per-day price breakdown rows where vars exist (`total_rooms_cost`, `total_extra_demands`, `total_additional_services`, `total_standalone_service_products`), tax label (incl/excl) per existing `$display_tax_label`/`$use_taxes` logic; total emphasized.
5. **Policy text** — existing policy vars/module output, small type.
6. **Quantity stepper** — per `quantity_field.tpl` (`quantity_wanted` hidden, cap `max_avail_type_qty`).
7. **CTA** — "Book now" (primary, pill, full-width) submitting form id `booking-form`; `displayBookingAction` hook output rendered inside/near CTA.

Accessibility: steppers keyboard-operable (buttons, not text-only), `aria-live="polite"` on price/total updates, contrast >= 4.5:1, focus rings visible.

## 11. Mobile Responsive Rules

- Breakpoints: phone <768 / tablet 768–1199 / desktop >=1200; mobile-first authoring.
- **No horizontal overflow at any width** — verify with QA captures at 375/768/1024/1440 px.
- Header: drawer nav on phone (hamburger), compact bar tablet, full bar desktop.
- Search bar: stacked + bottom-sheet guests (phone), 2-row (tablet), 1-row (desktop).
- Room page: sticky bottom booking bar (phone) → sheet; sidebar widget (desktop).
- Room cards: 1-col stacked (phone, image top), 2-col (tablet), 3–4 col (desktop).
- Footer columns collapse to accordion on phone.
- Touch targets >=44px; keyboard focus states; `prefers-reduced-motion` respected.
- Hindi/English: no fixed-width text containers without `overflow-wrap: anywhere` fallback; translations via `{l s='...'}` only — never hardcode user-facing English.

## 12. Performance Rules

- Body copy = system font stack (zero download). ONE display font (Fraunces) self-hosted woff2, ≤3 weights, latin subset, `font-display: swap` (~<60 KB total).
- New JS: vanilla, `defer`, no jQuery import in new code; bundle as single `theme.js`; target <25 KB gz. No new jQuery plugins. No carousels (CSS scroll-snap or static grids).
- CSS-only interactions preferred (hover/active/`:target` accordions where safe; drawer needs JS).
- Lazy-load below-fold images (`loading="lazy"` where template allows).
- Animate only `transform`/`opacity`. Target +CSS <30 KB gz.
- After any template/css change: `rm -rf cache/smarty/compile/* cache/smarty/cache/*` and `rm -f cache/class_index.php` (after override class changes).
